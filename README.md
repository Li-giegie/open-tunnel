# open-tunnel

`open-tunnel` 是一个使用 UDP 在多个客户端之间转发 IPv4 数据包的轻量级隧道程序。服务端负责维护客户端会话，并将隧道数据包转发给目标客户端；客户端通过系统 TUN 网卡收发数据。

> **注意**：本项目仍在开发中，尚未完成，功能和行为可能随时变更，请勿用于生产环境。

## 功能

- 基于 UDP 的客户端与服务端通信。
- 支持为服务端配置用户名和密码认证。
- 客户端通过心跳维持会话，服务端会清理超时会话。
- 跨平台支持：Linux 使用内核 TUN 网卡；Windows **依赖 [Wintun](https://www.wintun.net/) 虚拟网卡**（运行时加载 `wintun.dll`，缺少该文件客户端无法启动）。
- 可在客户端启动时配置 TUN 网卡的 IPv4 地址和 MTU。

## 通信流程

客户端与客户端之间不直接通信，所有流量经服务端转发。报文格式为 `Cmd(1 字节) + SessionId(8 字节) + Data`：

```text
                 客户端A                                服务端                                 客户端B
               (10.20.0.2)                         (转发中心)                              (10.20.0.3)
                    |                                   |                                   |
  1. 认证建立会话       ==============================================================================
                    |                                   |                                   |
                    |       AuthReq(用户名/密码)             |                                   |
                    |---------------------------------->|                                   |
                    | AuthResp(code=0, 分配sessionId)     |                                   |
                    |<- - - - - - - - - - - - - - - - - |                                   |
                    |                                   |                                   |
                    |  [创建 TUN 网卡]                      |                                   |
                    |  [配置 IPv4 地址和 MTU]                |                                   |
                    |                                   |                                   |
  2. 数据转发(客户端A -> 客户端B)           ==============================================================
                    |                                   |                                   |
                    |   Forward(sessionId + IPv4包)      |                                   |
                    |---------------------------------->|                                   |
                    |                                   | [提取源IP: 登记 隧道IP -> 客户端]           |
                    |                                   | [按目的IP查找目标客户端]                    |
                    |                                   |                                   |
------ 目的 IP 已登记      --------------------------------------------------------------------------
                    |                                   |     Forward(原样转发IPv4包)            |
                    |                                   |---------------------------------->|
                    |                                   |   [写入 TUN 网卡]                     |
                    |                                   |   [交由内核协议栈处理]                     |
                    |                                   |                                   |
------ 目的 IP 未登记(广播查询, 6s窗口去重)              ----------------------------------------------------
                    |                                   |    QuestionIP(广播查询目的IP)           |
                    |                                   |- - - - - - - - - - - - - - - - - >|
                    |                                   |         AnswerIP(目的IP)            |
                    |                                   |<- - - - - - - - - - - - - - - - - |
                    |                                   | [登记: 目的IP -> 客户端B]                |
                    |                                   |                                   |
  3. 心跳保活     ==================================================================================
                    |                                   |                                   |
------ loop: 每 keepalive 间隔    -----------------------------------------------------------------
                    |         Ping(sessionId)           |                                   |
                    |---------------------------------->|                                   |
                    |               Pong                |                                   |
                    |<- - - - - - - - - - - - - - - - - |                                   |
-------------------------------------------------------------------------------------------------
                    |                                   |                                   |
                    |                                   | [定期清理超过 health-timeout]           |
                    |                                   | [无活动的会话]                          |
                    |                                   |                                   |
```

几个要点：

- **IP 登记**：服务端在转发时从 IPv4 包头提取源 IP，自动建立 `隧道IP → 客户端` 映射，无需客户端显式上报。
- **未知目的 IP**：服务端通过广播 `QuestionIP` 查询 IP 归属，持有该 IP 的客户端回复 `AnswerIP`。本次触发的原始包会被丢弃，依赖上层协议（如 TCP）重传后送达。
- **回程流量**：B → A 的数据走完全对称的反向路径。

## 环境要求

- Go 1.26.8 或兼容版本，用于从源码构建。
- Linux 客户端需要启用 TUN，并具有创建 TUN 网卡和配置网卡的权限（通常使用 `root` 或 `CAP_NET_ADMIN`）；配置网卡时依赖 `ip` 命令。
- Windows 客户端需要：
  - **Wintun（必需依赖，缺少时客户端无法启动）**：从 [wintun.net](https://www.wintun.net/) 下载压缩包，解压后把对应架构的 `wintun.dll`（如 64 位系统取 `bin/amd64/wintun.dll`）放到 exe 同目录或 `System32` 下。
  - 以管理员权限运行（创建/删除网卡、配置 IP 和 MTU 都需要）。
- 服务端 UDP 端口需要允许客户端访问。

## 构建

```sh
git clone https://github.com/Li-giegie/open-tunnel.git
cd open-tunnel
go build -o open-tunnel .
```

Windows 下的可执行文件以 `.exe` 结尾：

```sh
go build -o open-tunnel.exe .
```

也可以用 `go run .` 直接运行。还可以在任意平台交叉编译，例如在 Linux 上构建 Windows 版本：

```sh
GOOS=windows GOARCH=amd64 go build -o open-tunnel.exe .
```

查看命令和参数：

```sh
./open-tunnel --help
./open-tunnel server --help
./open-tunnel client --help
```

## 使用

### 1. 启动服务端

在可被客户端访问的主机上运行：

```sh
./open-tunnel server --addr 0.0.0.0:9000 --users 'alice:change-me'
```

`--users` 可包含多个账号，以逗号分隔，例如 `alice:secret,bob:another-secret`。省略该参数时，服务端不校验用户名和密码。

### 2. 启动客户端

在每台客户端主机上分别运行，并为每台主机分配唯一的隧道 IPv4 地址。以下示例中，服务端地址为 `198.51.100.10:9000`。

Linux 客户端：

```sh
sudo ./open-tunnel client \
  --addr 198.51.100.10:9000 \
  --username alice \
  --password change-me \
  --interface-addr 10.20.0.2/24
```

Windows 客户端（需管理员权限的终端，如 PowerShell）：

```powershell
.\open-tunnel.exe client `
  --addr 198.51.100.10:9000 `
  --username alice `
  --password change-me `
  --interface-name open-tunnel `
  --interface-addr 10.20.0.3/24
```

另一台客户端使用相同的服务端和凭据，但应使用不同的地址，例如 `10.20.0.3/24`。

启动后，客户端会创建 TUN 网卡（Linux 默认名为 `tun0`，Windows 上通过 `--interface-name` 指定，例如 `open-tunnel`），设置 IPv4 地址和 MTU 并启用网卡。地址应在各客户端之间保持唯一；将客户端配置在同一隧道子网后，可通过隧道 IP 相互通信。

> Windows 客户端启动**必须**有 `wintun.dll`（见「环境要求」），否则程序无法运行。Linux 下的 `tun0` 是默认值，也可用 `--interface-name` 自定义。

## 命令行参数

### `server`

| 参数 | 默认值 | 说明 |
| --- | --- | --- |
| `--addr` | `0.0.0.0:9000` | UDP 监听地址 |
| `--users` | 空 | 逗号分隔的 `用户名:密码` 列表；为空时不启用认证 |
| `--health-interval` | `1m` | 服务端检查会话健康状态的间隔 |
| `--health-timeout` | `2m` | 客户端无活动超过此时间后清理会话 |

### `client`

| 参数 | 默认值 | 说明 |
| --- | --- | --- |
| `--addr` | `127.0.0.1:9000` | 服务端 UDP 地址 |
| `--username` | 空 | 认证用户名 |
| `--password` | 空 | 认证密码 |
| `--interface-name` | `tun0` | TUN 网卡名称 |
| `--interface-addr` | `192.168.10.1/24` | TUN 网卡 IPv4 地址和前缀，例如 `10.20.0.2/24` |
| `--interface-mtu` | `1450` | TUN 网卡 MTU |
| `--keepalive` | `15s` | 客户端发送心跳的间隔 |
| `--timeout` | `2m` | 客户端等待服务端响应的超时时间 |

## 安全说明

当前实现通过 UDP 明文传输认证信息和隧道数据，不提供加密或完整性保护。请仅在可信网络或受保护的网络通道中使用，并避免将未启用认证的服务端暴露到不可信网络。命令行密码也可能被本机进程信息读取。
